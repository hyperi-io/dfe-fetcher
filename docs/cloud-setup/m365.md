# M365 Setup for dfe-fetcher

What a cloud administrator needs to configure so dfe-fetcher can read
security and audit data from Microsoft 365.

## What dfe-fetcher Needs

An **Entra ID app registration** with application-level permissions for:

- **Office 365 Management Activity API** — audit logs, DLP events,
  message traces
- **Microsoft Graph Security API** — security alerts

dfe-fetcher authenticates via OAuth2 client_credentials flow using two
scopes:

- `https://manage.office.com/.default` (audit logs, message trace, DLP)
- `https://graph.microsoft.com/.default` (security alerts)

**Admin consent is required** — a Global Administrator or the
appropriate admin role must grant consent for the application
permissions.

## Required Permissions

| Service | API | Permission | App ID | Permission ID | Type |
|---------|-----|-----------|--------|---------------|------|
| **Audit Log** | Office 365 Management | `ActivityFeed.Read` | `c5393580-f805-4401-95e8-94b7a6ef2fc2` | `594c1fb6-4f81-4475-ae41-0c394909246c` | Application |
| **Message Trace** | Office 365 Management | `ActivityFeed.Read` | (same) | (same) | Application |
| **DLP** | Office 365 Management | `ActivityFeed.Read` | (same) | (same) | Application |
| **Alerts** | Microsoft Graph | `SecurityEvents.Read.All` | `00000003-0000-0000-c000-000000000000` | `bf394140-e372-4bf9-a898-299cfc7564e5` | Application |
| **Alerts** | Microsoft Graph | `SecurityAlert.Read.All` | (same) | `472e4a4d-bb4a-4026-98d1-0b0d74cb74a5` | Application |
| **Reports** | Microsoft Graph | `Reports.Read.All` | (same) | `230c1aed-a721-4c5d-9cb4-a90514e508ef` | Application |

All permissions are **application** (not delegated) and **read-only**.

## Terraform (Automated)

The test infrastructure is defined in
[`infra/test/main.tf`](../../infra/test/main.tf) (M365 section). It
creates an app registration with the exact permission IDs above, a
service principal, and a client secret.

```bash
cd infra/test
cp terraform.tfvars.example terraform.tfvars
# Authenticate: az login (must be in the target tenant)
terraform init
terraform apply
terraform output -json | python3 gen-env.py > ../../.env
```

**After apply**, grant admin consent (requires Global Admin):

```bash
az ad app permission admin-consent --id <m365_client_id>
```

Terraform cannot grant admin consent — this manual step is required.

## Manual Setup

1. **Create app registration**

   ```bash
   az ad app create --display-name "dfe-fetcher-m365"
   ```

2. **Add Office 365 Management API permission**

   ```bash
   az ad app permission add \
     --id <app_id> \
     --api c5393580-f805-4401-95e8-94b7a6ef2fc2 \
     --api-permissions 594c1fb6-4f81-4475-ae41-0c394909246c=Role
   ```

3. **Add Microsoft Graph permissions**

   ```bash
   # SecurityEvents.Read.All
   az ad app permission add \
     --id <app_id> \
     --api 00000003-0000-0000-c000-000000000000 \
     --api-permissions bf394140-e372-4bf9-a898-299cfc7564e5=Role

   # SecurityAlert.Read.All
   az ad app permission add \
     --id <app_id> \
     --api 00000003-0000-0000-c000-000000000000 \
     --api-permissions 472e4a4d-bb4a-4026-98d1-0b0d74cb74a5=Role

   # Reports.Read.All
   az ad app permission add \
     --id <app_id> \
     --api 00000003-0000-0000-c000-000000000000 \
     --api-permissions 230c1aed-a721-4c5d-9cb4-a90514e508ef=Role
   ```

4. **Grant admin consent**

   ```bash
   az ad app permission admin-consent --id <app_id>
   ```

5. **Create client secret**

   ```bash
   az ad app credential reset --id <app_id> --years 1
   ```

6. **Create service principal** (if not created automatically)

   ```bash
   az ad sp create --id <app_id>
   ```

7. **Activate audit log subscriptions**

   The Office 365 Management Activity API requires subscriptions to be
   started before content is available. Do this once per content type:

   ```bash
   TENANT_ID="your-tenant-uuid"
   TOKEN=$(az account get-access-token \
     --resource https://manage.office.com \
     --query accessToken -o tsv)

   for CT in Audit.General Audit.AzureActiveDirectory Audit.Exchange Audit.SharePoint DLP.All; do
     curl -X POST \
       "https://manage.office.com/api/v1.0/${TENANT_ID}/activity/feed/subscriptions/start?contentType=${CT}" \
       -H "Authorization: Bearer ${TOKEN}" \
       -H "Content-Type: application/json" \
       -d '{}'
   done
   ```

   This only needs to be done once. Subscriptions persist until
   explicitly stopped.

8. **Configure dfe-fetcher**

### Config File

```yaml
sources:
  m365:
    enabled: true
    tenant_id: "your-tenant-uuid"
    client_id: "your-client-uuid"
    client_secret: "your-client-secret"
    services:
      - name: audit_log
      - name: message_trace
      - name: dlp
      - name: alerts
    topic: "m365"
```

### Environment Variables

```bash
DFE_FETCHER_SOURCES__M365__ENABLED="true"
DFE_FETCHER_SOURCES__M365__TENANT_ID="your-tenant-uuid"
DFE_FETCHER_SOURCES__M365__CLIENT_ID="your-client-uuid"
DFE_FETCHER_SOURCES__M365__CLIENT_SECRET="your-client-secret"
```

### Secrets Manager (Production)

```yaml
sources:
  m365:
    enabled: true
    tenant_id: "your-tenant-uuid"
    credential_secret: "vault:secret/dfe/m365:credentials"
    services:
      - name: audit_log
      - name: alerts
    topic: "m365"
```

The vault secret should contain JSON:

```json
{
  "client_id": "your-client-uuid",
  "client_secret": "your-client-secret"
}
```

## Admin Consent Requirement

All permissions listed above are **application-level** and require a
Global Administrator (or Application Administrator with appropriate
scope) to grant consent. Without admin consent, API calls will return
`403 Forbidden`.

Verify consent status:

```bash
az ad app permission list-grants --id <app_id>
```

## Multi-Tenant

To fetch from multiple M365 tenants (e.g., managed service provider
scenario), run a separate dfe-fetcher instance per tenant. Each needs:

- Its own app registration in that tenant
- Admin consent granted in that tenant
- Audit subscriptions activated in that tenant
- A distinct `instance_id` in the fetcher config
